# Scheduler Execution Fix - Summary

## Problem

The automatic research scheduler was **NOT running**, even though:
- Automatic mode was enabled in the UI
- 60-minute interval was configured
- The database showed "Automatic" mode selected

**Root Cause**: The `run_streamlit.py` launcher script only started the Streamlit UI server but **never launched the background scheduler daemon** (makemoney.py). Without the daemon process running the async event loop, no cycles were ever claimed or executed.

## Solution Implemented

### 1. Modified `run_streamlit.py`
Updated the launcher to start **BOTH** services:
- **Streamlit UI Server** (port 8501) - User interface
- **Scheduler Daemon** (makemoney.py) - Background event loop

Key changes:
```python
# Before: Only ran Streamlit
subprocess.run(cmd, check=True)

# After: Starts scheduler daemon, then Streamlit, with cleanup on exit
scheduler_process = subprocess.Popen([sys.executable, "makemoney.py"], ...)
try:
    subprocess.run(cmd, check=True)
finally:
    scheduler_process.terminate()  # Cleanup when Streamlit exits
```

## How It Works

1. **Initialization** (on start):
   - run_streamlit.py launches makemoney.py daemon and Streamlit UI
   - makemoney.py enters event loop: `asyncio.run(main())`

2. **Monitoring Loop** (every 10 seconds):
   ```python
   while True:
       if claim_due_research_cycle():
           logger.info("Scheduled research cycle starting")
           await run_trading_cycle()
       await asyncio.sleep(min(10, settings.news_interval_seconds))
   ```

3. **Claiming Cycle** (when due):
   - `claim_due_research_cycle()` atomically updates `research_schedule_last_run`
   - Only returns True if current_time > last_run + interval_minutes
   - Prevents concurrent cycle execution

4. **Executing Cycle**:
   - `run_trading_cycle()` performs:
     - Candidate research (using OpenAI if enabled)
     - Risk assessment
     - Trade execution
     - Analytics recording

5. **Database Tracking**:
   ```sql
   SELECT * FROM app_settings WHERE key='research_schedule_last_run';
   -- Returns: 2026-10-05T15:53:21.596481+00:00 (UTC timestamp)
   ```

## Technical Details

### Event Loop Timing
- Scheduler checks every 10 seconds if cycle is due
- Prevents busy-waiting: uses `asyncio.sleep(10)`
- News fetches every 3600 seconds (1 hour) as separate task
- Trading cycles run only when due (every 60+ minutes by default)

### Clock Dependencies
- All times use UTC with timezone awareness
- Database stores ISO 8601 timestamps
- Next run = last_run + interval_minutes (no drift)
- Scheduler stops if system suspended between checks (requires resume_date configuration)

### Concurrency Safety
- SQLite CONFLICT resolution: only one process can claim cycle
- `INSERT ... ON CONFLICT(key) DO UPDATE` ensures atomic update
- Multiple instances cannot double-run same cycle
